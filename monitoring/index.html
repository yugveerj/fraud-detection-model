Methodology

  • PSI on dense inputs + the score distribution only. Sparse block-NaN Vesta V*/id_* features are excluded — their PSI is small-sample NaN noise, not drift (D-008).
  • Structural-time features excluded from drift PSI. Causal aggregates (ent_*) grow as an entity accumulates history, and the calendar-position transforms (dt_day, dt_dow) encode when a ~2-day batch falls on the clock — both shift by construction under forward replay, not from data/concept drift (D-008, D-013). Intra-day timing (dt_hour, dt_is_night) is kept.
  • Value-capture baseline = the out-of-time norm (the model's holdout value capture at the frozen threshold), so the performance guard fires on new degradation rather than the known validation→holdout gap (D-013).
  • Cadence: one simulated week (of TransactionDT) per scheduled run; the stream freezes with a final report when exhausted.
  • Replay + label lag: a replayed simulation on a static dataset (banner above). This replay has labels immediately; in production fraud labels arrive weeks late, so live monitoring watches input + score drift, not just outcomes.
