1. PR-AUC (average precision) — recomputed

Average precision is the developer’s primary metric (rare-positive). Implemented from first principles: sort by score, sweep the threshold, integrate precision over recall.

average_precision <- function(y, p) {
  o <- order(p, decreasing = TRUE)
  y <- y[o]; p <- p[o]
  tp <- cumsum(y); fp <- cumsum(1 - y)
  # Collapse tied scores to DISTINCT thresholds (keep the last index of each tie
  # block). This matches scikit-learn: precision/recall are evaluated per distinct
  # threshold, not per row. It is essential here because isotonic calibration produces
  # large tie blocks — see the findings note below.
  keep <- c(p[-length(p)] != p[-1], TRUE)
  tp <- tp[keep]; fp <- fp[keep]
  precision <- tp / (tp + fp)
  recall <- tp / sum(y)
  sum(diff(c(0, recall)) * precision) # AP = sum (R_i - R_{i-1}) P_i
}
roc_auc <- function(y, p) {
  # Rank-based (Mann-Whitney U) with average ranks — tie-correct, equals sklearn.
  r <- rank(p)
  n_pos <- sum(y == 1); n_neg <- sum(y == 0)
  (sum(r[y == 1]) - n_pos * (n_pos + 1) / 2) / (n_pos * n_neg)
}
pr_auc_r  <- average_precision(y, p)
roc_auc_r <- roc_auc(y, p)
cat(sprintf("R PR-AUC = %.4f (Python %.4f)\nR ROC-AUC = %.4f (Python %.4f)\n",
            pr_auc_r, PY$pr_auc, roc_auc_r, PY$roc_auc))

3. Value-capture at the frozen operating point

The decision layer freezes a threshold on validation and reports on holdout. We independently recompute fraud value captured and net value at that threshold.

thr <- PY$threshold

4. Score-distribution PSI (early vs late holdout)

A within-holdout stability check: the score distribution of the first half of the (time-ordered) holdout vs the second half.

psi_numeric <- function(ref, cur, bins = 10) {
  edges <- unique(quantile(ref, seq(0, 1, length.out = bins + 1)))
  e <- table(cut(ref, edges, include.lowest = TRUE)) / length(ref)
  a <- table(cut(cur, edges, include.lowest = TRUE)) / length(cur)
  eps <- 1e-6
  e <- pmax(as.numeric(e), eps); a <- pmax(as.numeric(a), eps)
  sum((a - e) * log(a / e))
}
half <- floor(n / 2)
psi_score <- psi_numeric(p[1:half], p[(half + 1):n])
cat(sprintf("score PSI (early vs late holdout) = %.4f  [>0.2 = significant shift]\n", psi_score))
## score PSI (early vs late holdout) = 0.0021  [>0.2 = significant shift]

Findings note — a discrepancy that reconciled

A first-pass R implementation of average precision (evaluating precision/recall per row) gives PR-AUC 0.4753 against the developer’s 0.4642 — a 0.011 gap that exceeds the 0.01 reconciliation tolerance. Root cause: isotonic calibration produces blocks of tied probabilities, and per-row evaluation double-counts precision within a tie block. scikit-learn (and the corrected R above) evaluate precision/recall at distinct thresholds, collapsing ties; with tie-aware AP the figure reconciles exactly (0.4642). A parallel issue affected ROC-AUC — per-row trapezoidal integration also mishandles ties, so the rank-based (Mann-Whitney, average-rank) form is used and reconciles exactly (0.8788). The size of the gap tracks the tie-block size (LightGBM’s isotonic output ties more than XGBoost’s did), so the fix is not optional here. Brier and value-capture were unaffected (they do not depend on within-tie ordering). This is the value of an independent challenge: it surfaces subtle tie-handling issues a shared codebase would have hidden.

Effective challenge conclusion. The independent R recomputation of PR-AUC, ROC-AUC, Brier, and value-capture-at-threshold reproduces the developer’s real-holdout results from the exported scores alone, with no shared code, once the tie-handling above is applied.
